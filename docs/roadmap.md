### ステップ5のメモ（本物に近いピアノの音）
- 理由：iPadで機器の音量を下げると、ほかのアプリより小さく聞こえる。アプリ側の音量の余裕は使い切っていて、合成の音を明るくすると音の質が落ちた（technical-notes.md の「音の明るさ」）。録音された音は、小さなスピーカーで聞こえやすい高めの成分を自然に含むので、音の質を保ったまま聞こえやすくなる見込み
- いまの合成のピアノは消さずに残す（ユーザーの希望）。「音色」に録音のピアノを足す形にする
- 決めること・調べること：無料で使える音源とライセンス表記、ファイルの大きさ（数MB）と読み込みの待ち時間、iOSのChromeで読み込めるファイル形式、音の高さごとに何個録音を持つか（間の音は再生の速さを変えて作る）、聴感補正やコンプレッサーとの組み合わせ
- 判定つき・曲の練習など、ほかの機能でも録音のピアノで鳴るようにする

### ステップ5の調査結果（1回目・2026-11-02）
5は「調べて決める回」と「作る回」の2回に分ける。調べた結果と、決めてもらうこと：

- 音源の候補
  - **VCSL（Versilian Community Sample Library）の「Grand Piano, Steinway B」（おすすめ）**
    - ライセンスは CC0（パブリックドメインと同じ。表記の義務なし、商用も可）。リポジトリの LICENSE ファイルで確認した（github.com/sgossner/VCSL）
    - 全音ごと（ド・レ・ミ・ファ♯・ソ♯・ラ♯）に録音されている：ラ♯0〜ソ♯7の42音。間の音は再生の速さを1半音分だけ変えて作れる（音色の変化はほとんどない）
    - 強さは3段階（vl2・vl3・vl4）。音量はそろえて（ノーマライズして）あり、強さのちがいは音色（明るさ）のちがいとして残っている
    - 「NoSus」（ペダルなし）と「Sus」（ペダルあり）がある。アプリではサスティンを自前で行うので「NoSus」を使う
    - 録音は44.1kHz・24bit・ステレオのWAV。最初の音の立ち上がりは先頭からすぐ始まる（前の無音はない）
    - 長さ（vl3）：ラ♯0 約22秒、ド2 約32秒、ド4 約18秒、ド6 約9秒、ソ♯7 約2秒
  - 同じ VCSL の「Grand Piano, Kawai」（CC0、強さ4段階）：録音した音の間隔がそろっていない（3〜5半音あくところがある）ので2番手
  - 同じ VCSL の「Upright Piano, Yamaha」（CC0）：ドとソだけ（5〜7半音ごと）で、間の音を作ると音色が変わりやすい
  - Salamander Grand Piano（Yamaha C5）：ライセンスは CC BY 3.0（作者名の表記が必要）。2022年にパブリックドメインになったという説もあるが、作者のページでは確かめられていない。VCSL があるので使わない
  - アイオワ大学の楽器音（MIS）：自由に使えるという説明と、再配布は許可が必要という説明が混在しているので使わない
- ファイル形式：**MP3**（iPad・iPhoneのどの版でも読める）
  - Ogg Vorbis・Opus は iOS 18.4 以降でしか読めないので使わない。AAC（m4a）も読めるが、MP3と大きさは同じくらい
  - MP3・AACは、作るときに先頭へ短い無音（0.02秒くらい）が入ることがある。読み込んだあと、最初に音が始まる位置を探して、そこから鳴らす
- 大きさ・読み込み
  - モノラル（ステレオの左右を混ぜる）、96kbps、1音の長さは最長8秒（最後をフェードアウト）にすると、37音で約3MB（64kbpsなら約2MB）。ド4を8秒にしたもので、96kbps＝約97KB、64kbps＝約65KB
  - 鍵盤の音域はド1〜ド7なので、そのうちド1〜ド7の37音を使う（ラ♯0とド7より上は使わない）
  - 読み込み：4G回線で数秒、Wi-Fiなら1秒前後の見込み。一度読み込めばブラウザに残る。読み込みは開始画面のタップの前から始め、終わるまでは合成のピアノで鳴らし、「ピアノの音を読み込み中」と出す
  - 再生用に展開すると、メモリを約50MB使う見込み（モノラル・最長8秒）。iPadでは問題ない大きさだが、実機で確かめる
- いまの仕組みとの組み合わせ
  - 録音の音も、合成の音と同じ形（out・oscs・release）にして TONES に「録音のピアノ」として足す。鳴らし方・止め方・サスティン・判定つき・曲の練習は、そのまま使える
  - 聴感補正：録音の音も voiceBus（低い音の250Hzより下を弱める）を通す。音の高さごとの補正の表（LOUDNESS_TABLE）は、tools/loudness で録音のピアノの分を測って作る。合成のピアノで行っている「低い音ほど倍音を増やす」は、録音には使えない（録音にはもともと倍音が含まれている）
  - 音割れ防止（コンプレッサー・リミッター）はそのまま通す
- 決めてもらうこと（試聴用のファイルで聴きくらべる）
  1. 音源：VCSL の Steinway B でよいか
  2. 強さ：vl2（やわらかい）・vl3（ふつう）・vl4（明るい）のどれにするか。iPadで小さく聞こえる問題には、明るいほうが効く見込み
  3. 音質：96kbps（約3MB）か64kbps（約2MB）か
  4. 1音の長さの上限：8秒でよいか（全音符をゆっくり弾いても足りる長さ。長くするほどファイルとメモリが増える）
- 2回目（作る回）ですること：WAVからMP3を作る開発用の道具（tools/ に置く。ffmpeg を使う）、sounds/ への音源の追加、audio.js に録音のピアノの音色を追加、読み込み中の表示、聴感補正の表の追加、音源の出典（CC0・VCSL）を技術メモとREADMEに書く

### ステップ5-2のメモ（押している間だけ効くペダル）
- 理由：本物のピアノのペダル（右のダンパーペダル＝サスティン）は「踏んでいる間だけ」効き、和音が変わるたびに「離して、すぐ踏み直す」。いまの画面の「サスティン」ボタンは押すたびにオン・オフが切り替わるので、この動きを練習できない。PCではスペースキーを押している間だけ効く（keyboard.js）
- 決めたこと（2026-11-02）：
  - iPadなど大きい画面では、鍵盤の近くに横長の「ペダル」欄を出し、指で押さえている間だけサスティンを効かせる。片方の指でペダルを押さえたまま、ほかの指で鍵盤を弾ける（Pointer Events は複数の指を同時に扱える）
  - 大きい画面では、設定「ペダル」で「押している間（ペダル欄）」と「切り替え（ボタン）」を選べるようにする（ユーザーの希望）。選んだ方だけを出し、設定は localStorage に保存する。最初は「押している間（ペダル欄）」にする
  - スマホは画面が狭いので、いまの切り替え式のボタンのまま（ペダル欄も設定「ペダル」も出さない）
  - 大きい画面とスマホの分け方は、設定のたたみ・開きと同じ「画面の短い辺が600px以上」を目安にする（app.js の applyControlsOpen）
- 作るときに気をつけること：
  - いまのサスティンは「鍵盤ピアノ」モードのときだけ（ボタンは data-modes="piano"、スペースキーも鍵盤ピアノのときだけ）。ペダル欄も同じにする
  - ペダル欄に触れた指で鍵盤が鳴らないようにする（鍵盤のグリッサンド処理と分ける）。指がペダル欄の外に出ても、離すまでは踏んでいる扱いにする（setPointerCapture）
  - pointercancel・画面を離れたとき（visibilitychange）・モードを切り替えたときは、ペダルを離した扱いにする（音が鳴り続けないように）
  - 踏んでいる間は見た目で分かるようにする（色を変えるなど）
  - 設定「ペダル」は、ペダル欄・ボタンと同じく「鍵盤ピアノ」モードのときだけ出す。押している間（ペダル欄）からボタンに切り替えたときは、サスティンをオフにしておく
  - ペダル欄の分だけ鍵盤が小さくならないよう、置き場所を決める（2段表示のiPad縦向き・1段表示のiPad横向きの両方で確かめる）
  - 「サスティン」の言葉は残す（設定・PCのスペースキーと同じ動き）。ペダル欄の表示は「ペダル（押している間）」など
- 候補に残したもの（features.md）：Bluetoothのフットペダル、ソフトペダル、ソステヌートペダル、曲データのペダル記号と判定
- 5-2（初版・2026-11-02）でできたこと：大きい画面（短い辺600px以上）の鍵盤ピアノで、鍵盤の下に横長の「ペダル（押さえている間だけ効く）」欄を出した。押さえている間は青くなり「ペダル：踏んでいます」と出る。片方の指でペダル欄を押さえたまま、ほかの指で鍵盤を弾ける。設定「ペダル」で「押している間（ペダル欄）」と「切り替え（ボタン）」を選べる（最初は押している間）。スマホはいままでどおり切り替え式のボタンだけ
  - 置き場所：鍵盤の下（本物のピアノのペダルと同じ向き）。高さ56px。ヘッドレスブラウザで、iPad縦向き（2段）・横向き（1段）・iPad mini横向きとも、鍵盤の高さが前の版と同じ（ペダル欄の分は、表示エリアが小さくなる）ことを確かめた
  - PCのスペースキーも「押している間」として同じ仕組みで扱い、押している間はペダル欄も青くなる
- 実機で確かめること：ペダル欄を押さえたまま鍵盤を弾けるか（複数の指）、和音を変えるときの「離して、すぐ押さえ直す」がやりやすいか、ペダル欄の位置と高さ（手のひらが触れて効いてしまわないか、画面の下の端のホームバーの操作とぶつからないか）、ペダル欄から指を滑らせて出たときも効き続けるか

### ステップ2のメモ
- 片手ずつ練習・部分ループには「曲のデータ」「決まったタイミングで音を鳴らす仕組み」「鍵盤を光らせる表示」が必要。これらはお手本再生を作る中でできあがるので、お手本再生を先に作る順番に変えた（2-1 → 2-2 → 2-3）
- 曲データは右手・左手を分けて持てる形式にする
- 2-1（初版）でできたこと：モード「曲の練習」。曲を選んで再生すると、鳴っている音の鍵盤が光る（右手＝オレンジ、左手＝紫）。テンポは再生中でも変えられ、曲ごとに保存。鍵盤の位置は曲に合わせて自動で決まる（2段のときは右手を下段、左手を上段に）。収録曲：きらきら星、メリーさんのひつじ、よろこびの歌（著作権の切れた曲。左手の伴奏はこのアプリ用に付けたもの）
- 2-2（初版）でできたこと：曲の練習で「両手（お手本）・右手・左手」を選べる。進み方は「弾くまで待つ」（次に弾く鍵盤が光り、正しく弾くまで止まって待つ。タイミングは判定しない）と「テンポ通り」（練習する手は鳴らさず光るだけ）。もう片方の手は「自動で鳴らす・鳴らさない」。弾くまで待つときはミスの数を数え、最後まで弾くと「最後まで弾けました！ミス○回」と出る
- 2-2であわせて直したこと：設定項目が増えてスマホで操作パネルが画面の半分を占めたので、「設定」ボタンでたためるようにした（スマホは最初からたたむ）。表示エリアの高さは中身に合わせて測るようにした
- 2-3（初版）でできたこと：曲の練習の画面で「○〜○小節」を選ぶと、その区間だけを練習できる（区間は曲ごとに保存）。「くり返し：オン」にすると区間の最後で最初に戻り、停止ボタンを押すまでくり返す。両手（お手本）・右手・左手、弾くまで待つ・テンポ通りのどれとも組み合わせられる。くり返し中は「○回目」を表示し、弾くまで待つときはその回のミスと前の回のミスを出す。くり返しがオフなら区間を1回弾いて止まる（「区間を弾けました！」）。鍵盤の位置は区間の音に合わせて決める
- 部分ループで今後足せること：うまく弾けたら（ミス0回など）少しずつテンポを上げる、くり返しの間に1小節分の間（カウント）を入れる、再生中にくり返しのオン・オフを切り替える
- 今後足せること：一時停止・途中から再生、カウント（再生前の「1・2・3・4」）、五線譜での表示、曲の追加、片手練習の記録（ミスの数の履歴）、ミスの多い場所の表示

### ステップ2-4・2-5のメモ（タイミング・音の長さの判定）
- ユーザーの希望：タイミングと音の長さを判定し、音ゲーのように評価を出したい。少しずれても先に進めるようにする
- 実装はブラウザでも可能。難しいのはスマホの遅れ（画面に触れてから届くまで＋スピーカーから音が出るまで）。iOSは特に遅れが大きく、Bluetoothイヤホンだと0.15〜0.25秒ほど遅れる
- 対策：
  - タイミング調整：一定のテンポのクリック音に合わせて8回ほどタップしてもらい、平均のずれを端末ごとに保存して、判定のときに差し引く
  - 判定の幅をゆるめにする（目安：パーフェクト ±0.06秒、グレート ±0.12秒、グッド ±0.2秒、それより外はミス）。速い曲で幅が音の間隔より広くならないよう、半拍を上限にする
  - 押した時刻はイベントの timeStamp を使い、AudioContext の getOutputTimestamp で音の時刻に直す（処理の遅れの影響を受けないように）
- 進み方に3つ目の「判定つき」を足す：テンポ通りに進み、練習する手の音ごとに判定する。グッドの幅を過ぎても弾かなければ止まって待つ（＝少しずれても進むが、大きく遅れたら待つ）
- 音の長さ：離した時刻を音の終わりと比べ、「短め・ちょうど・長め」をタイミングの評価とは別に出す（ピアノは音の長さの許容が広いので、ゆるめにする）
- 結果の表示：パーフェクト・グレート・グッド・ミスの数、正確さ（％）、曲・練習する手ごとの最高記録
- 評価の文言は日本語（カタカナ）にする（CLAUDE.md の「画面の文言はすべて日本語」）
- 実装するとき、CLAUDE.md の「厳密なリズム判定は避ける」を「判定はゆるめの幅とタイミング調整で行い、大きく遅れたら止まって待つ」に書き換える
- 2-3（部分ループ）の後に作る：苦手な区間をくり返しながら評価を上げる練習ができる
- 1回の作業を1機能にするため、タイミング（2-4）と音の長さ（2-5）に分けた
- 2-4（初版）でできたこと：片手練習の進み方に「判定つき」を追加。1小節分のカウント（クリック音）のあと、テンポ通りに進み、練習する手の音ごとにパーフェクト・グレート・グッド・ミスと「はやい・おそい」を出す。グッドの幅を過ぎても弾かなければミスにして、弾くまで止まって待つ。ちがう鍵盤を押したときもミスに数える。正確さ（％）を表示し、最後まで弾くと内訳・正確さ・最高記録（曲・練習する手・区間ごと）を出す。部分ループと組み合わせると、回ごとの正確さと前の回の正確さを出す
- 2-4の「タイミング調整」：判定つきのときに設定に出る。クリック音に合わせて8回タップすると、ずれの中央値を端末ごとに保存し、判定のときに差し引く
- 2-4であわせて直したこと：画面に入りきらないとき（スマホ横向きで設定を開いたときなど）、表示エリアが鍵盤や操作パネルと重なっていたので、重ならずに画面全体をスクロールできるようにした
- 2-5（初版）でできたこと：判定つきで、タイミングが当たった音（パーフェクト〜グッド）は、離したときに押していた時間を楽譜の長さと比べ、「長さ ちょうど・短め・長め」を出す。タイミングの判定とは別で、正確さ（％）には入れない。最後まで弾くと「音の長さ ちょうど○ 短め○ 長め○」を出す。判定つきのときは、色の見本（右手・左手）の行を音の長さの行に置きかえた（スマホ横向きで高さを増やさないため）
- 2-5で今後足せること：音の長さの判定のきびしさを選べるようにする、音の長さも最高記録に残す、押している間に「もう離してよい」ことがわかる表示（鍵盤の光り方を変えるなど）
- 2-4で今後足せること：判定の幅の「きびしさ」を選べるようにする、テンポ通り・弾くまで待つにもカウントを入れる、ミスの多い場所の表示

- 2段表示の上段（左手の音域）の音が小さく聞こえる → 1回目（低い音の音量を上げる）では直らなかった。2回目で、人の耳の感度と小さなスピーカーの特性を考えた聴感補正を入れ、コンプレッサーのかけ方を見直した（technical-notes.md の「聴感補正」）→ 実機で差を感じなくなった。音割れもなし
- iPadで機器の音量を下げると、ほかのアプリより小さく聞こえる（アプリの音量は100）→ 測るとアプリの音はほかのアプリの基準（−14 LUFS）より大きかったので、iOSの音の扱い（メディア再生ではない）が原因と推定。無音の音声を再生する方法を試したが、もともと消音モードでも音が出ていた（＝メディア再生として扱われていた）ので効果がなく、外した。次の候補は音色（小さなスピーカーで聞こえやすい高い成分が少ない）→ 設定「音の明るさ」（明るめ・とても明るめ）を試したが、音の質がよくないので外した。録音されたピアノの音（ステップ5）で対応する
- 新しい版がiPadに出ない（2026-11-01）→ GitHub Pagesの公開が「前の公開が途中（in progress deployment）」と続けて断られていた。前の公開から20〜25分ほどあけずに次を公開すると断られた。「Re-run jobs」でのやり直しは順番待ちのまま動かなかった。GitHub側の既知の不具合とみられる（technical-notes.md の「公開（GitHub Pages）で困ったとき」）。間をあけて新しく push すると公開できる
- しばらく使っていると音が出なくなった → iOSで音が中断された状態から戻れていなかったと推定。再開画面と作り直しで対応。実機ではChromeの再起動で直った（Chrome側の一時的な不調だった可能性もある）
